# BazutteでYouTubeを調べる

自然文の依頼から調査目的と必要なデータを決め、数値とリンクを根拠に答える。分析前の接続確認や利用枠確認は必須にしない。具体的な依頼があれば、その調査から始める。

## 目的に合う調査を選ぶ

| 目的 | 調べ方と比較の観点 |
| --- | --- |
| 伸びている動画を探す | `get_video_ranking`で候補を取得する。再生数の多さ、最近の伸び、登録者規模に対する広がり、同じチャンネルの普段との差を区別し、依頼に合う指標を選ぶ。条件に使った登録者数や比較指標も結果に含める。 |
| 競合を比較する | `get_channels`で候補と一覧の指標を調べる。動画・ショート・ライブの種別、対象期間、登録者規模をそろえる。必要な詳細だけ`get_channel_detail`で補う。一覧で答えられる比較では各チャンネルの詳細を追加取得しない。 |
| 自分のチャンネルを分析する | `get_channel_detail`で依頼に関係する指標と推移を読む。再生数・登録者数の変化、投稿件数、動画種別の構成を整理する。投稿や動画別の履歴は、差の原因を調べるために必要な場合だけ追加する。 |
| 過去の投稿や動画の推移を調べる | 投稿一覧は`get_channel_videos`、動画の指標履歴は`get_video_history`。投稿の公開期間と、指標を記録した期間を混同しない。 |
| 次の企画を考える | まず関連する動画・競合のデータを取得する。繰り返し見られる傾向から企画案を作り、根拠、試す内容、結果を判断する指標を添える。タイトルだけで内容や人気の原因を断定しない。 |

「伸びている」の意味を利用者の文脈から選ぶ。判断できない場合はツールの既定の指標を使い、採用した意味を短く示す。独自スコアの定義はツール説明に従い、再生数の順位を期間内の増加量として扱わない。

## 条件を決めて取得する

利用可能なBazutte MCPツールの説明と入力スキーマを正とする。クライアントによって名前に接頭辞が付く。存在しないツール・引数・任意の日付ランキングを作らない。

省略できる条件はツールの既定値を使い、不要な確認を増やさない。上位10件なら10件を取得し、比較に必要な指標とリンクを選ぶ。次ページは返された情報を使い、依頼に必要な件数で止める。各ツールの取得上限を超えた場合は、取得範囲を明記する。

チャンネルの表示名や`@handle`をIDとして送らない。名前しか分からない場合は候補を探し、複数の候補から特定できなければ選んでもらう。

過去投稿の取得にはチャンネルIDと利用者が指定した公開期間の開始日・終了日が必要。期間は勝手に決めず、未指定なら確認する。1回の公開期間は最大397日なので、長い期間は分けて取得する。チャンネル詳細の投稿プレビューに`detail_arguments`があれば引き継ぐ。動画履歴は動画IDが必須で、記録日範囲は任意。

## 調査結果を使える形で返す

最初に依頼への答えを示す。比較では同じ指標を同じ列に並べ、差が分かる形にする。対象期間・種別・絞り込み条件・取得件数を短く添え、動画とチャンネルは返されたURLへリンクする。詳しい分析を見る導線には、返されたBazutteのURLも使える。

確認できた数値と解釈を分ける。再生数の累計、期間内の増減、登録者数、増加率を混同しない。履歴の累計を日別増分として扱わず、記録がない日をゼロで補わない。更新日時があれば示し、リアルタイムの数値や全投稿の収集を保証しない。空結果は「指定条件に合う保存データがなかった」と伝える。

企画案を求められたら、取得した傾向を根拠に提案し、未検証の仮説であることを示す。依頼が一覧取得だけなら、追加の企画案や長い解説を付けない。公開されている読み取りツールを使い、任意SQLや書き込み操作は行わない。

## 使い方・利用枠・エラーの案内

使い方だけを尋ねられた場合は、動画発見・競合比較・チャンネル分析の質問例を2〜3件示す。質問例のためだけに分析データを取得しない。

利用枠を尋ねられたら`get_mcp_usage`を呼ぶ。`remaining_percent`と、返された場合の`resets_at`を使い、日本時間で残りとリセット日時を伝える。利用枠はすべてのAIで共通で、この確認自身は枠を消費しない。

認証・権限・利用枠のエラーでは同じ呼び出しを繰り返さず、原因に合う操作を案内する。認証エラーは使用中のクライアントで再認証する。Codexでは`codex mcp login bazutte`、Claude Codeでは`claude mcp login plugin:bazutte:bazutte`を案内し、ブラウザで接続を許可して新しい会話を開いてもらう。権限エラーはBazutteアカウントのMCP利用権限、利用枠の超過は返されたリセット日時を確認する。別のAIで同じ利用枠を回避しようとしない。

ツールを使えなければ、データを取得できていないと伝える。結果の代わりに架空の応答や数値を出さない。OAuth認証は利用者本人が行い、トークンやパスワードを会話へ貼るよう求めない。導入方法は[配布元のREADME](https://github.com/bazutte/bazutte-plugins)を案内する。
